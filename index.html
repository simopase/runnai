END-TO-END FLOW

From a run to tokens — five stages.

The same infrastructure powers the wallet, the sponsor dashboard and the AI gateway.
01 · RUNwatch / treadmill

The user moves; the device records GPS, heart rate, cadence.

02 · VERIFY9 checks

The anti-fraud pipeline scores the session (trust 0.5–1.2×).

03 · MINT20 cr/km

Credits are written to the wallet ledger, backed by the compute pool.

04 · ROUTERunnaI Auto

The gateway picks the model per step: cheap first, frontier when needed.

05 · SETTLEactual usage

Real token usage is metered and charged in credits; the rest is released.

Technical appendix

How km become credits.

The technical core of Move-to-Compute: a transparent conversion formula, fraud-resistant verification and an economic peg that keeps every credit backed by real compute.

THE CONVERSION

One formula. Five signals.

Every verified session is scored with the same expression before a single credit is minted — no hidden bonuses, no manual adjustments.
credits=km×base×type×effort×trust
TERMMEANINGRANGE
kmverified distance—
basepool-backed rate20 cr/km
typeactivity multiplier0.25–1.0×
effortHR-zone intensity0.8–1.3×
trustanti-fraud reputation0.5–1.2×
All values are illustrative. One credit ≈ €0.01 of retail compute value; the base rate is the only variable the platform tunes — and it is set by the compute pool, not by marketing.

THE PEG

Every credit is backed by compute.

The base rate is not a marketing number: it is derived each month from the compute pool funded by sponsors and subscriptions.
base=monthly pool÷projected verified km
INPUTSOURCEVALUE
Compute poolsponsors + subscriptions12M cr
Projected verified kmnext 30 days600,000
Base rate12M ÷ 600k20 cr/km
Daily cap per useranti-farming600 cr
Anti-inflation by construction: if verified km grow faster than the pool, the rate drops automatically. Credits can never exceed the compute that backs them — the supply is elastic, the peg is not.
VERIFICATION PIPELINE

From watch to wallet, through five gates.

A session is paid only after passing every stage. Failures are flagged for review — never silently paid.
01 · INGESTGPS · HR · cadence

Raw session from watch, phone or treadmill.

02 · VALIDATE9 checks

Pace variance, GPS continuity, HR coherence, replay detection — and more.

03 · ATTESTdevice ID

Signed payload from the wearable SDK or OEM partnership.

04 · SCORE0.5–1.2×

Trust score adjusts the payout; anomalies are flagged, not paid.

05 · MINTledger entry

Credits written with source, km and multipliers — fully auditable.
